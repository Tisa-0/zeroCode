# Operation Node Migration Plan

## Scope

This document maps the 12 operation nodes:

- `join`
- `union`
- `transform`
- `sample`
- `sort`
- `pivot`
- `unpivot`
- `group`
- `selfloop`
- `mirror`
- `deduplicate`

Goal: migrate these capabilities into backend-independent modules, while keeping current UI and behavior.

## Node-by-Node Migration Matrix

1. `join`
- Current execution: backend SQL join via `unionType/unionFields`.
- Migration action: keep SQL join builder as first-class independent domain service (`JoinSqlBuilder`), isolate from `io.dataease.extensions.*` DTOs.

2. `union`
- Current execution: graph preview path; not unified into main SQL planner.
- Migration action: create `UnionExecutor` with two modes: `all` and `distinct`; unify preview and query paths.

3. `transform`
- Current execution: config-only, no backend execution.
- Migration action: define expression DSL + `TransformExecutor`; first support calculated-field projection.

4. `sample`
- Current execution: backend graph preview and local preview both supported.
- Migration action: move into independent executor module and remove duplicated frontend-only logic.

5. `sort`
- Current execution: backend uses `sortFields`; node config exists separately.
- Migration action: unify node `sort` config -> backend `sortFields` mapper in one adapter (`SortConfigMapper`).

6. `pivot`
- Current execution: config-only.
- Migration action: implement `PivotExecutor` based on `group + aggregate + column expansion`.

7. `unpivot`
- Current execution: config-only.
- Migration action: implement `UnpivotExecutor` with column-to-row transformation.

8. `group`
- Current execution: backend graph preview supported.
- Migration action: extract `GroupAggregateExecutor`, later apply to non-preview query path.

9. `selfloop`
- Current execution: config-only.
- Migration action: implement recursive hierarchy expansion executor with `idColumn/parentIdColumn/maxDepth`.

10. `mirror`
- Current execution: source passthrough and graph traversal resolving.
- Migration action: keep as graph-level alias node in independent graph engine (`MirrorResolver`).

11. `deduplicate`
- Current execution: backend graph preview supported.
- Migration action: extract `DeduplicateExecutor`, support pushdown-to-SQL when datasource supports window functions.

## Recommended Extraction Order

1. Build independent graph domain model (`ArrangeGraph`, `ArrangeNode`, `ArrangeEdge`, `OperationConfig`).
2. Extract currently implemented executors first: `join`, `union`, `sample`, `group`, `deduplicate`, `mirror`.
3. Wire backend preview/query to new executor registry.
4. Implement missing executors: `transform`, `pivot`, `unpivot`, `selfloop`.
5. Remove direct business dependence on DataEase-specific DTOs from executor internals.
